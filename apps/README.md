# apps

Create apps here with:

    python3 tools/new_app.py --name ctrlx-<company>-<app> --title "<Title>" --author "<Company>" --url <url>

Each app folder can also become its own git repository.

| App | What | Status |
|---|---|---|
| `ctrlx-core-monitor` | Status of other ctrlX COREs (host name, IP, firmware, CPU, memory) via Data Layer remote connections; connections in app data, "+ Add core" dialog | 0.1.1 - verified 2026-10-22: amd64 on the COREvirtual (watching a 4.6 and a 3.6 CORE), arm64 on the real CORE (watching the COREvirtual); UI checked in the browser |
| `ctrlx-amr-fleet` | Live map of AMRs: positions/headings written as one JSON string to the Data Layer node `ctrlx-amr-fleet/fleet/amrs`; occupancy map (bundled `HMI_Map.txt` or app data) as tiles; pan, zoom, pinch, lock (heading-up), minimap, AMR list with detail tiles; driven paths per AMR; help menu with GitHub link and tutorial; styling settings; read-only users without settings; ctrlX home screen widget; simulation with collision avoidance | 0.3.0 (paths, help, tutorial) installed on the COREvirtual and the real CORE 2026-10-24: checked on the COREvirtual (API, ui_check --device), memory/load re-measured on the CORE (README) - 0.2.4 installed on the COREvirtual (amd64) and the real CORE (arm64) on 2026-10-24 and performance-tested before/after (0.2.2) with a 103 x 177 m map and 10-200 simulated AMRs on both (results in its README); app, ui_check --device and home screen widget verified on the COREvirtual (0.2.0) |
| `ctrlx-network-scanner` | Network inventory of the CORE's networks: host discovery (neighbor table/ARP, TCP, mDNS/SSDP/WS-Discovery), TCP/UDP ports, services (banners, HTTP, TLS certificates, automation identification), MAC vendors; scan profiles with load limits and schedules; whitelist/blacklist rating, change detection, history, PDF/CSV/JSON reports; Data Layer start/abort + results | 0.1.0 - 2026-10-25: arm64 on the real CORE (LAN /24 in 15 s, CPU <= 10 %, 42 MB), amd64 on the COREvirtual (Data Layer start/abort, schedule, automation identification, PDF, UI via reverse proxy); details in its CHANGELOG |
| `ctrlx-system-analyzer` | Temporary diagnostic app: CPU and memory of the system and of every app (snap), process and thread from `/proc` (strict + `system-observe`), RAM history in three tiers (5 s / 1 min / 10 min, min/avg/max), leak analysis (lower-envelope trend in MB/h, fit, time until full), restart/update events and markers, optional CSV recording to an external medium (`removable-media`), CSV/JSON export, uPlot charts | 0.1.1 - 2026-10-30: arm64 on the real CORE (2.4-2.7 % of one core at 5 s, 57 MB RSS, synthetic leak rated "growing" after 30 min, recording to a USB stick and reading it back after a restart, device clock 7 days off handled); 0.1.0 - 2026-10-27: amd64 on the COREvirtual (plugs connected by the installer, 0.6 % CPU at 5 s, 68.5 MB RSS after 1 h, UI via reverse proxy, Data Layer nodes, a synthetic leak rated "growing" after 30 min); details in its CHANGELOG |
